# AGENTS.md

Context for any coding agent (Antigravity, Claude Code, etc.) working in this repo.

## What this is
A RAG chatbot that answers customer questions about refrigerators using the
manufacturer's manual PDFs, meant to be embedded on a support website.
Portfolio/case-study project — code quality and clear README/architecture
documentation matter as much as the app working.

## Stack and why
- **Backend**: Python, FastAPI, ChromaDB (local, persisted to disk), Gemini API
  (`gemini-embedding-001` for embeddings, `gemini-2.5-flash` for generation).
- **No LangChain/LlamaIndex.** PDF parsing, chunking, and prompt construction
  are hand-rolled in `backend/app/pdf_utils.py` and `backend/app/rag.py` on
  purpose, so the mechanics stay readable and explainable. Don't introduce a
  RAG framework unless explicitly asked — it would hide the parts of this
  project that are meant to demonstrate understanding.
- **Frontend**: plain HTML/CSS/JS (`frontend/`), no build step, so it stays a
  simple embeddable widget. Don't add a framework/bundler unless asked.
- **Embeddings via API, not a local model.** Deliberately avoids
  sentence-transformers/PyTorch so the backend stays light enough for a
  512 MB free-tier host (Render free tier). Keep it that way unless the
  deployment target changes.

## Key files
| File | Purpose |
|---|---|
| `backend/app/pdf_utils.py` | PDF text extraction (+ OCR fallback for scanned pages), chunking, manual-name parsing |
| `backend/app/image_utils.py` | Diagram/photo extraction from PDFs (PyMuPDF), filtered by size |
| `backend/app/embeddings.py` | Gemini embedding calls (ingestion + query) |
| `backend/app/vectorstore.py` | Chroma wrapper — embedding-agnostic, takes precomputed vectors |
| `backend/app/rag.py` | Retrieval + grounded prompt + generation |
| `backend/app/ingest.py` | CLI: builds the index from `backend/data/manuals/*.pdf` |
| `backend/app/main.py` | FastAPI routes (`/api/ask`, `/api/health`) |
| `frontend/script.js` | Chat widget logic, calls the API |

## Conventions
- Manual PDFs are not committed (see `.gitignore` and README) — they're
  usually copyrighted by the manufacturer. Don't add manual PDFs to git.
- `backend/vectorstore/` is a build artifact, regenerated by
  `python -m app.ingest`. Don't commit it.
- The system prompt in `backend/app/config.py` enforces grounding (answer
  only from retrieved excerpts, say so when they don't cover something,
  flag disagreement across models/manuals). Don't relax this without a good
  reason — it's the main thing stopping the assistant from confidently
  making up appliance instructions.
- Every retrieved chunk carries `manual` (friendly model label) and `page`
  metadata; keep citing both in responses and in `Source` objects.

## Before running
```bash
cd backend
cp .env.example .env        # then add GEMINI_API_KEY
pip install -r requirements.txt
# add manual PDFs to data/manuals/, or generate a placeholder:
#   pip install -r requirements-dev.txt && python data/generate_sample_manual.py
python -m app.ingest
uvicorn app.main:app --reload
```
Then open `frontend/index.html` (its `config.js` defaults to
`http://localhost:8000`).

## Known limitations worth knowing before "fixing"
- OCR fallback (for scanned manuals) is Tesseract at 200 DPI — noisier on
  diagram-heavy pages, fine on body text. Don't be alarmed by imperfect OCR
  chunks from those pages.
- Chunking is sentence-greedy with character-based overlap, not
  layout-aware. Multi-column safety pages occasionally interleave; a
  layout-aware extractor (pdfplumber) is the natural upgrade if this
  becomes a real problem.
